## Current state
Three parallel deliverables now exist, each serving a different purpose:
1. **`index.html`** — the original static demo, still live at **https://vpm-voter-guide.vercel.app** (Vercel project `mark-hayes-projects/vpm-voter-guide`). Good for presenting/sharing a link.
2. **`wordpress-embed.html`** — single self-contained paste for a WordPress Custom HTML block (all CSS scoped under `.vpm-vg`, images pointed at the Vercel deployment).
3. **`acf-sections/*.html`** + **`wordpress-template/`** — the real path being pursued for VPM's actual WordPress site (`vpmnews.kinsta.cloud`), described below.

**`acf-sections/`** splits the page into 7 independently-movable fragments (Header, Section Nav, Video Coverage, Key Virginia Elections, Key Regional Races, Voting FAQ, Newsletter) for pasting into separate ACF Code blocks, so Mark can reorder them and intersperse native WordPress content between them. **Paste order and all the rules are now documented in `acf-sections/README.md`** — read that first.

As of 2026-08-04 these fragments follow the `vpm-page-builder` skill's conventions:
- **Featured Stories is no longer hardcoded.** `header-section.html` ends at a `<!-- ===== SPLIT ===== LIVE BLOCK HERE: Featured Stories (article list) ===== -->` marker; the editor inserts a live 3-column Article List block there (title field left empty), and the stylesheet restyles that block's own classes (`section.page-article-grid`, `.page-article-card.PromoA`, `.bsm-img-ph`, …) to match the retired static cards. Those overrides are the only un-prefixed selectors in the sheet, are clearly fenced off in a `LIVE BLOCK OVERRIDES` section, and redeclare the custom properties because the live block renders outside `.vpm-vg`.
- **The sticky "On this page" nav moved out** of `header-section.html` into its own `section-nav.html`, because in the design it sits *below* the Featured Stories cards — i.e. on the far side of the split.
- Featured Stories moved out of the two-column hero row into its own full-width band (a split can't happen mid-grid).

**`wordpress-template/`** is a newer, likely-better path: a proper WordPress **page template** (`page-voter-guide.php`) instead of the row/Code-block builder. This was scoped as a proof-of-concept — only **Important Dates** (ACF repeater) and **Latest Coverage** (WP_Query by category, ACF text field `coverage_category`) are wired to live/editable data; Featured Stories, Elections cards, Regional cards, and FAQ are still static HTML pending Mark's sign-off on the editing experience. Ad slots are restored to their original nested positions via `do_shortcode('[vpm_section id="..."]')` with obvious `REPLACE_WITH_..._AD_ID` placeholders — **not yet swapped for real ids**. **Never executed against real WordPress/PHP** — no PHP CLI was available locally, only manually reviewed for syntax/control-flow balance.

## Decisions made (and why)
- **All class names in `acf-sections/*` and `wordpress-template/page-voter-guide.php` carry a `vg-` prefix** (`.wrap`→`.vg-wrap`, `.sidebar`→`.vg-sidebar`, etc.) — see Gotchas, this fixed a real production bug where VPM's WordPress theme already defined CSS for these exact generic names.
- **Ad placeholders were removed from `acf-sections/*`** (all three: 970×90, 300×250, 300×600) — Mark confirmed his CMS's blocks (Code blocks, `[vpm_section id=...]` shortcode) cannot nest inside each other's HTML, only sit as independent sibling blocks/rows. The leaderboard becomes its own full-width row; the two side-by-side ads need a 2-column builder row (confirmed his builder supports this).
- **Pivoted toward a PHP page template instead of continuing the ACF-sections/row-builder split** — a page template has no nesting restriction at all (real PHP can call `do_shortcode()` or `WP_Query` anywhere, including nested inside custom layout), which directly solves the ad-placement problem AND keeps "Latest Coverage" genuinely dynamic (a live query) instead of a manually-updated static grid. Trade-off: not visually editable in wp-admin — structural changes need a code edit (theme file access via Kinsta SFTP/file manager, which Mark hadn't confirmed he has as of this session).
- **ACF fields chosen for Important Dates + Coverage Category specifically** (not the other 4 sections yet) because this recurs every election cycle (primary + general, annually) and Mark wanted to evaluate the wp-admin editing experience on one concrete section before committing to converting the rest.
- **Featured Stories deliberately NOT auto-queried** — when that section does get ACF-ified (follow-up, not done), use a Post Object/Relationship repeater (hand-picked posts) rather than "most recent N," since featured stories are curatorial, not just recency-sorted.

## Gotchas / things that will bite you
- **The scrollspy was silently dead in the ACF split** (fixed 2026-08-04). The nav script runs inline, but `#video`/`#elections`/`#regional`/`#faq` live in *later* Code Blocks, so at parse time `getElementById` returned null for all of them and the IntersectionObserver observed nothing. Setup now waits for `DOMContentLoaded`. Two related fixes in the same script: the activation band is a thin strip under the sticky nav (`rootMargin:'-64px 0px -70% 0px'`), and `setActive` picks the *last* overlapping section, not the first — otherwise the outgoing section, whose bottom edge exactly meets the band, kept the highlight.
- **Margins collapse out through the bottom of a fragment.** The Featured Stories label's `margin-bottom` escaped `.vpm-vg` (no padding/border to stop it) and rendered as a white strip above the live block. Any element at the very bottom of a fragment needs its margin zeroed or the wrapper needs padding.
- **The live Article List block renders OUTSIDE `.vpm-vg`**, so it inherits none of the custom properties and none of the scoped resets. Its overrides redeclare what they need under `section.page-article-grid`. Don't "fix" it by trying to wrap the live block.
- **`_shared-styles.html` is generated from `header-section.html`'s `<style>` block** — edit the header, then regenerate, never edit the copy. When extracting, anchor the regex to a line-start `^<style>`: the doc comment at the top of `header-section.html` mentions `<style>` in prose, and a naive match pulls comment text into the CSS, which silently kills the custom-property block (whole page renders white-on-black-less).
- **Generic class names collide with WordPress theme CSS.** VPM's live theme already defines styles for common names like `.wrap` and `.sidebar`; because our own CSS never set an explicit background on those specific elements, the theme's rule just applied outright with no specificity fight — this caused a white background to leak into the Header section on the live site while everything else rendered fine. Fixed by prefixing every class name with `vg-` throughout `acf-sections/*` and `wordpress-template/page-voter-guide.php`. **Do not reintroduce unprefixed generic class names in this design.**
- **The CMS cannot nest one block/shortcode inside another's HTML** — confirmed directly by Mark testing it. A Code block's raw HTML output does not get passed through `do_shortcode()` or similar; `[vpm_section id="..."]` only works as its own independent block. This is *why* the page-template approach exists — don't try to fix this by editing the ACF Code-block HTML again, it structurally can't work that way.
- **No PHP CLI available in this environment** — `page-voter-guide.php` was verified only by manual brace/tag/control-flow counting and a hand-built static preview (PHP blocks swapped for sample data), never actually executed. Treat it as unverified until Mark runs it on real WordPress.
- **The project folder is under `~/Projects/vpm/vpm-voter-guide/`, not flat under `~/Projects/`** — matches the general VPM project-layout convention; don't assume the flat path.
- Ad-blocker cosmetic-filter collision (from the earlier session) still applies — class names like `ad-slot`/`ad-300x250` get hidden by EasyList-style blockers; already renamed to `promo-slot`/`slot-*` in `index.html`/`wordpress-embed.html` (not applicable in `acf-sections`/`wordpress-template`, which removed the ad placeholder divs entirely).
- `header-section.html` got accidentally converted to a `.txt` file mid-session (Finder mishap) and had to be fully reconstructed from the still-intact `_shared-styles.html` — the shared stylesheet file is a genuinely useful recovery anchor if any single fragment gets corrupted again.
