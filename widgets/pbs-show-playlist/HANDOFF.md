## Decisions made (and why)
- **Re-entered CF Worker secrets fresh, didn't chase further root-cause** — PBS's own docs-example endpoint (`GET /shows/{id}/`) returned `{"detail":"Invalid key/secret."}"` even after PBS confirmed the credentials were active/production. Re-running `wrangler secret put` for both `PBS_API_KEY` and `PBS_API_SECRET` with freshly copy-pasted values fixed it immediately. Not worth further investigation now that it works — see Gotchas if this recurs.
- **Switched the `sort` param from `-air_date` to `-encored_on`** — `air_date` isn't a real PBS field (confirmed via the `meta.sort` block in PBS's own response, which only lists `encored_on`/`premiered_on`/`updated_at`); the previous code was silently sorting by an ignored/default order instead of true recency. The README always documented `-encored_on` as intended — this was a code/doc mismatch, now fixed.
- **Added `type=full_length` to the `/assets/` filter** — without it, PBS returns a mix of `full_length`/`clip`/`preview` assets, and Virginia Home Grown posts many short topical clips per episode. The un-filtered query was returning 5 clips from a single episode, not 5 distinct episodes — a direct contradiction of the brief's "5 episode thumbnails." Confirmed `type` is a valid filter via the `meta.filter` block in PBS's own response.
- **Rewrote the player-embed logic to use PBS's own `player_code` field instead of a constructed URL** — the original code tried to build `https://player.pbs.org/widget/partnerplayer/{tp_media_object_id}/?callsign=...`, but real PBS asset responses have no `tp_media_object_id` field at all, and the real player URL shape is completely different (`https://player.pbs.org/partnerplayer/{token}/?topbar=...&autoplay=...`, no callsign param). This was designed against assumed API shape before real credentials ever worked, and was never actually exercised until today. Now the widget extracts the `src` straight out of the `player_code` iframe HTML PBS already returns, and toggles `autoplay=true/false` on that same URL for the autoplay-to-next behavior. `CALLSIGN` config is now dead and was removed.
- **Removed the temporary `/_health` diagnostic route** added mid-session to isolate whether the 401 was PBS-side or ours (it hit PBS's plain `/shows/{id}/` doc example, bypassing the `/assets/` filter). Not needed now that the real issue (bad secrets) is fixed and confirmed.

## Gotchas / things that will bite you
- **The 401 was resolved by simply re-entering the same credentials PBS said were already valid** — root cause was never conclusively identified. If this widget (or any future PBS Media Manager integration) hits a 401 again, don't assume it's automatically PBS-side just because support says the creds are active; try a clean `wrangler secret put` re-entry first, since that's what actually fixed it here.
- **PBS Media Manager has no flat episodes-by-show endpoint.** Season-aware episode listings need `shows/{id}/seasons` → `seasons/{id}/episodes`. This widget deliberately uses `/assets/?show-id=&type=full_length` instead, which is simpler and gives the player-ready `player_code` field directly.
- **`/assets/` real filter params, confirmed from PBS's own response `meta.filter` block**: `id`, `slug`, `show-id`, `show-slug`, `special-id`, `special-slug`, `episode-id`, `episode-slug`, `type`, `platform-id`, `platform-slug`. Valid `sort` fields (from `meta.sort`): `encored_on`, `premiered_on`, `updated_at` only — no `air_date`.
- **PBS's real player embed is the `player_code` field on each asset, not a URL you construct yourself.** It's a full `<iframe>` HTML string; extract `src` from it rather than assuming any ID field maps to a player URL path.
- **PBS docs site (docs.pbs.org) needs a JS-rendering browser, not a plain fetch** — WebFetch/curl return an empty shell. Use a real browser (Playwright navigate + snapshot) to read it. The full endpoint/filter/sort reference lives on the linked "Resources" sub-page, not the main "Media Manager API" page.
- **PBS API ToS forbids advertising/sponsorship "in association with" PBS content/player** — this is the biggest open compliance risk, not a technical one. Still unresolved.
- **Two Cloudflare Worker secrets needed**: `PBS_API_KEY` and `PBS_API_SECRET` (set via `npx wrangler secret put <NAME> --profile vpm`, run from inside `~/Projects/vpm/pbs-api` — wrangler errors with "Required Worker name missing" if run from the wrong directory since it can't find `wrangler.jsonc`).
- **An iframe embed needs an explicit auto-resize mechanism — `aspect-ratio` on the `<iframe>` tag does nothing.** `aspect-ratio` only derives a size when the element has *some* natural ratio to work from; a plain iframe doesn't have one, so it silently falls back to the browser default height. Confirmed by a real ACF paste: the widget rendered inside a ~100px box with the whole thing scrolling internally. Fixed with a `postMessage`-based resize (widget → parent page), but the first attempt at this used `document.documentElement.scrollHeight`, which is **floored by the iframe's own current viewport height** — it can grow the iframe but can never report a smaller value once the iframe has already grown once (confirmed: stayed pinned at 714px after a viewport narrow-down that should have shrunk the 16:9 player significantly). The fix is to measure the widget's own root element (`root.getBoundingClientRect().height`) instead — its box height is driven purely by its content, not the iframe's current size. If any future iframe-embedded widget needs this pattern, use the root-element approach from the start.
